# CLAUDE.md — public/data

The app's static data, served at `/data/<name>` in dev and production.
Referenced by absolute path from `src/studyArea.js`.

See `spec.md` here for the exact image and GeoJSON format requirements. Read
it before adding or replacing any file in this folder.

## None of this is real

Every file was generated by `../../scripts/make_sample_data.py`. The geography
is real; the imagery, risk numbers and hazard polygons are invented.

## Contents

**Radar images** — `radar_YYYY-MM-DD.png`, 512×512 greyscale, 12 days apart.
Darker = less radar signal returned (smooth or wet ground: open water, fresh
ash). Brighter = rough ground (vegetation, buildings, caldera wall). Across
the series a dark patch spreads north-east from the Nakadake vent.

Twelve PNGs exist but `studyArea.js` references only six (`2026-09-08`
through `2026-11-07`). The six dated June–July 2026 are orphans from an
earlier generator run. Deleting them changes nothing.

**Hazard zones** — five GeoJSON files, each with two polygons (`medium` and
`high` rings) centred on the vent. High = ballistics and pyroclastic flow,
medium = ashfall. `risk_zones.geojson` is the observed set, used on every past
date; the four `risk_forecast_*.geojson` files are per-date predictions whose
rings widen toward the predicted peak on `2026-12-13` and then pull back.

## Hard requirements when replacing data

1. **Images must cover exactly `studyArea.bounds`**, north-up, unrotated, all
   at identical pixel dimensions. The overlay is placed by corner coordinates,
   not embedded georeferencing — a mismatched image is silently stretched and
   every brightness reading becomes wrong without any error.
2. **PNGs must be greyscale.** The app reads the red channel only.
3. **Every GeoJSON feature needs a `properties.risk`.** `"high"` renders red;
   *any other value* renders amber. There is no `low` styling and no
   validation.
4. Coordinates are `[longitude, latitude]`; rings must close.

## Procedure for swapping in real data

1. Produce PNGs and GeoJSON meeting the above.
2. Drop them here.
3. Update `dates` and `forecast` in `src/studyArea.js`.
4. Set `isSample: false`.

Do not delete `make_sample_data.py` — it is the specification-by-example for
everything in this folder.

## Failure behaviour

A missing PNG surfaces as `Could not load <url>` in the side panel and
disables the brightness chart and change mode. A missing GeoJSON logs a
MapLibre source error and renders nothing, with no UI message.
